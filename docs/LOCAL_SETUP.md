# Run Sentinel locally

## Prerequisites

- Git and Node.js 22.12+ (or Node.js 24 LTS).
- Docker Desktop with Compose v2 on macOS/Linux, or Docker Engine + Compose v2 on Linux. On macOS, Colima is also supported: `brew install colima docker docker-compose`.
- Python 3.9+ for the small managed-lab host. The API runs Python 3.12 inside Docker. Native API development and backend tests require Python 3.12.
- About 6 GiB RAM and 12 GiB free disk for the isolated SDN VM/images. The initial build needs internet.

Windows: use a Linux WSL2 checkout, Docker integration, and Python inside WSL2. Native Windows lab hosting is not supported.

## Start the complete Docker application

```bash
git clone https://github.com/PraneethPW/SENTINALSDN.git
cd SENTINALSDN
npm run local:up
npm run local:credentials
```

Open **http://localhost:5180**. Sign in with the generated credentials. The API is **http://localhost:8100** and PostgreSQL is bound to loopback port **55432**. No root npm install, cloud account, API key, or model download is needed for this path.

The launcher uses a working Docker context. If no daemon is available on macOS, it starts the separate Colima `sentinel-sdn` profile. To choose one explicitly:

```bash
SENTINEL_DOCKER_CONTEXT=desktop-linux npm run local:up
# Or Colima:
SENTINEL_DOCKER_CONTEXT=colima-sentinel-sdn npm run local:up
```

The stack includes PostgreSQL, schema migrations, the FastAPI API, the verified trained model, the Nginx frontend, and an isolated three-switch Mininet network. Allow 60–90 seconds for the first real counter window. It also starts a checkout-scoped managed-lab host; it does not install a macOS login service. New private accounts can start their own lab from **Network setup** while that host is running.

```bash
npm run local:status
npm run local:logs
npm run local:down
```

`local:down` drains managed jobs and stops this checkout's lab-host process before stopping Compose. Database and spool volumes remain for the next startup. Do not use `down -v` unless you deliberately want to erase local records.

## Environment files

`.env.example` is a **file**, not a directory. Copy only the example for your execution mode:

| File | Copy to | Purpose |
| --- | --- | --- |
| Root `.env.example` | `.env.local-stack` | Optional Docker ports, credentials, Google and AI settings. Blank secrets are generated by the launcher. |
| `backend/.env.example` | `backend/.env` | Native Python API configuration, database URL and model digest. |
| `frontend/.env.example` | `frontend/.env.local` | Vite proxy target and public production API URL. |

The default Docker startup generates `.env.local-stack` automatically and restricts permissions to its owner. Set optional values **before** starting/rebuilding:

```bash
cp .env.example .env.local-stack
# Edit .env.local-stack, then:
npm run local:up
```

Required local values generated automatically: `LOCAL_DB_PASSWORD`, `LOCAL_COLLECTOR_TOKEN`, `LOCAL_LAB_HOST_TOKEN`, `LOCAL_ADMIN_PASSWORD`. `LOCAL_ADMIN_EMAIL` defaults to `admin@sentinel.local`. The launcher computes `LOCAL_MODEL_SHA256` and `LOCAL_MODEL_THRESHOLD` from the committed artifacts.

Optional Google: set `LOCAL_GOOGLE_CLIENT_ID` and `LOCAL_GOOGLE_CLIENT_SECRET`. Register `http://localhost:5180/api/auth/google/callback` as an authorized redirect URI and `http://localhost:5180` as an origin in your Google web application. If using Vite, also authorize `http://localhost:5173`; the callback still runs through port 5180. Without these values, use email sign-in.

Optional AI: set `LOCAL_OPENROUTER_API_KEY` and optionally `LOCAL_OPENROUTER_MODEL`. Detection, benchmark evaluation and telemetry work without AI. All `VITE_*` variables are public: never put credentials or database URLs there.

Changing the generated database password after a volume has been initialized does not change PostgreSQL's stored password. Preserve the generated file, or rotate the database role explicitly. Bootstrap account credentials likewise only create the initial account; editing the file does not reset its password.

### Port conflicts and independent checkouts

Change `LOCAL_FRONTEND_PORT`, `LOCAL_API_PORT`, and `LOCAL_DB_PORT` in `.env.local-stack`. For an independent stack use `SENTINEL_STACK_NAME`; each project has separate volumes. Use the **same overrides for every lifecycle command**:

```bash
SENTINEL_STACK_NAME=sentinel-review npm run local:up
SENTINEL_STACK_NAME=sentinel-review npm run local:status
SENTINEL_STACK_NAME=sentinel-review npm run local:down
```

`SENTINEL_LOCAL_ENV_FILE` selects a different ignored env file. `SENTINEL_PYTHON` selects the Python executable for the managed-lab host. Use separate checkouts for independently running lab hosts.

## Frontend development with hot reload

Start the Docker stack, then in another terminal:

```bash
npm --prefix frontend ci
cp frontend/.env.example frontend/.env.local
npm run dev:ui
```

Open **http://localhost:5173**. Keep `VITE_API_URL=` empty to use Vite's same-origin HTTP/WebSocket proxy. `API_PROXY_TARGET` defaults to `http://127.0.0.1:8100`; change it when you customize the local API port. Restart Vite after env changes. An explicit `VITE_API_URL` is now honored in development as well as in production; avoid leaving a production URL in local env files.

## Native Python API

Use a separate development PostgreSQL database. From `backend`:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pip install -e '.[dev]'
cp .env.example .env
```

Edit `DATABASE_URL` to your own PostgreSQL URL. Generate a collector token with `python -c 'import secrets; print(secrets.token_urlsafe(48))'` and paste it into `COLLECTOR_TOKEN`. Keep `MODEL_PATH=artifacts/model.joblib` and the included model's `MODEL_SHA256` from the example. Run from `backend` so relative paths resolve:

```bash
python -m app.db
python -m app.admin your@email.com
uvicorn app.main:app --host 127.0.0.1 --port 8100
```

The admin CLI prompts for a password of at least 14 characters. Open `/docs` on the API during development. Run the frontend as described above. The native API alone does not start Mininet or a managed lab host; use collector setup or the complete Docker path for live SDN traffic.

## Tests and reproducible verification

```bash
npm --prefix frontend ci
npm test
npm run build
```

For backend tests, install the native Python development dependencies and set `TEST_DATABASE_URL` to a **dedicated disposable database whose name contains `_test`**:

```bash
TEST_DATABASE_URL=postgresql://user:password@localhost:5432/sentinel_test npm run test:api
```

Integration fixtures truncate tables in that test database. Never use your running application's database. Without `TEST_DATABASE_URL`, database integration tests are skipped.

After the Docker lab has produced flows, and after installing the Python requirements into `backend/.venv`:

```bash
npm run verify:local
```

This validates readiness, real switch/host discovery, model inference, flow export, 20 concurrent HTTP reads, 20 authenticated WebSockets, and viewer/operator role restrictions. It writes ignored results under `backend/work/` and creates local QA accounts only.

Public deployment smoke check:

```bash
npm run verify:deployment
# Optional URLs for a different environment:
SENTINEL_FRONTEND_URL=https://your-frontend.example SENTINEL_API_URL=https://your-api.example npm run verify:deployment
```

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Docker not found or cannot connect | Start Docker Desktop/Engine or install Colima; select a working `SENTINEL_DOCKER_CONTEXT`. |
| Port already in use | Set the three local port values and, for an independent checkout, `SENTINEL_STACK_NAME`. |
| Benchmark unavailable | Check API logs, `MODEL_PATH` and `MODEL_SHA256`. The hash must match `shasum -a 256 backend/artifacts/model.joblib`. |
| Vite API errors | Leave `VITE_API_URL` empty and point `API_PROXY_TARGET` at the running API; restart Vite. |
| No flows immediately | First poll establishes a baseline. Wait 60–90 seconds, then inspect collector/controller logs. |
| Private lab host offline | Inspect `backend/work/lab-host/host.log`; restart with `local:up`, and keep the Mac/VM awake. |
| Google button unavailable | Optional provider values are missing. Use email or configure the exact callback. |
| API readiness 503 in production | Inspect Railway database-connection logs and Neon availability. A running process does not prove database readiness. |

See [deployment configuration](DEPLOYMENT.md), [managed lab lifecycle](MANAGED_LABS.md), and [detection methodology](DETECTION_LAB.md).
