# Security and operations

Authentication uses Argon2 password hashes and random opaque sessions. Only SHA-256 token digests are stored in PostgreSQL. Sessions expire after eight hours by default and are revoked on sign-out. Session tokens are kept in browser sessionStorage so separate Vercel/Railway domains work without third-party cookies. This is a deliberate cross-origin tradeoff: maintain the CSP, avoid untrusted script injection, and use SSO/MFA before deploying in an enterprise environment requiring it.

Sign-in attempts are limited per normalized email using transaction locks and PostgreSQL counts. This initial implementation is a single workspace, with administrator/operator/viewer roles. It is not a multi-tenant SaaS. Add perimeter IP throttling, organization isolation, MFA/SSO, password recovery, formal model approval, and resource testing before widening the audience or exposure. The collector bearer token grants machine ingestion/command access across this workspace; provision separate scoped machine identities before onboarding untrusted agents.

API bodies have a 2 MB limit. Telemetry is validated for counts, intervals, IPs, switches, protocols, and timestamps. A batch is limited to 1,000 flows and 256 switches. All SQL values are parameterized. Public health probes expose only liveness/readiness. Production disables the Swagger UI. No endpoint accepts model binaries or arbitrary controller URLs.

The API never directly reaches a public controller address. Commands travel through PostgreSQL to a collector on the private network, with bounded scopes and a hard timeout. The included controller REST listener binds to loopback. The lab's privileged Docker container is confined to a dedicated Linux VM and must not be placed on a host with sensitive workloads. No packet-flood or public-target attack scripts are included.

Live subscriptions read persisted snapshots and revalidate the session every three seconds. Tickets are single-use and valid for 30 seconds. Polling the database, rather than in-process-only event delivery, keeps state consistent across API replicas, at the cost of database reads per subscriber. Load-test before increasing subscribers or traffic. The current ingestion loop is intended for bounded research/lab and modest deployments; use bulk inserts, partitioned flow storage, a queue, and fanout infrastructure if measured capacity requires them.

Structured request logs include a request ID, method, path, status, and duration, never authorization headers or payloads. API process restarts do not erase telemetry, sessions, commands, or incidents. Back up Neon, test restore, monitor database storage and collector lag, and use the automatic hourly retention job. Investigate collector `.rejected` files rather than replaying stale records as current.

Model artifacts use joblib and are loaded only after matching an operator-configured SHA-256. Keep artifact provenance and scikit-learn runtime versions aligned. The supplied dataset model is a baseline evaluated on a public Mininet lab, with limited recall at the default threshold. It is not a guarantee of attack detection, and an empty incident list does not prove network safety.

OpenRouter receives counts/protocol/model evidence only, with no IP addresses or notes. Free models have variable availability, can return incorrect analysis, and are outside the critical detection path. Read your provider's data policy before using sensitive operational metrics. The integration caps requests per operator and stores successful analysis in PostgreSQL. No AI output is executed.
